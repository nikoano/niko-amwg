# niko-amwg

Сервер AmneziaWG **поколения 3** (сейчас 3.1) на голой убунте: официальные пакеты
Amnezia, ядерный модуль, конфиг с полной обфускацией и своя утилита управления
клиентами. Без докера, без веб-панели, без официального клиента с деплоем по ssh.

Три файла:

| Файл | Что это |
|---|---|
| `install.sh` | ставит всё за один заход, в стиле `curl … \| bash` |
| `amwg.py` | утилита управления клиентами (ставится как `/usr/local/bin/amwg`) |
| `README.md` | вот это |

## Быстрый старт

```sh
curl -fsSL https://raw.githubusercontent.com/nikoano/niko-amwg/master/install.sh | bash -s -- --endpoint 1.2.3.4
```

или, если папка уже лежит на сервере (тогда `amwg.py` берётся из неё, а не из сети):

```sh
bash install.sh --endpoint 1.2.3.4 --port 443
```

Тот же url зашит дефолтом в `install.sh` (`AWG_REPO_RAW`) и нужен ровно за одним:
дотянуть `amwg.py`, когда установщик прилетел через пайп и рядом с ним ничего нет.
Своя ветка или форк — переменная окружения `AWG_REPO_RAW` либо одна строка в шапке
скрипта.

Скрипт **неинтерактивный**: через пайп спрашивать нечего, всё задаётся флагами.
После установки сразу заводится первый клиент и печатается его qr — телефон можно
подключить, не набрав больше ни одной команды.

Повторный запуск ничего не ломает: конфиг интерфейса не трогается (обновятся
пакеты и `amwg`), клиенты остаются на месте.

## Почему именно так

- **Поколение 3, а не 1.5.** Версии AmneziaWG между собой несовместимы, и все
  популярные панели (`wg-easy` с `EXPERIMENTAL_AWG`, форки `amnezia-wg-easy`)
  умеют только 1.5: `Jc/Jmin/Jmax`, `S1-S4`, `H1-H4`, `I1-I5`. Ни защиты
  заголовков, ни паддинга контента, ни таймингов, ни 3.1-фич там нет. Именно они
  и есть ответ на то, чем ТСПУ занялся летом 2026 — на анализ поведения
  соединения целиком, а не сигнатуры отдельного пакета.
- **Ядерный модуль, а не `amneziawg-go`.** Официальный клиент по ssh
  разворачивает контейнер, внутри которого крутится userspace-реализация на go.
  Контейнер там ради удобства GUI, а не ради дела: на голом железе ядерный модуль
  и быстрее, и проще в эксплуатации. Userspace остаётся запасным вариантом
  (см. «Если модуль не встал»).
- **Свой `amwg`, а не панель.** `amneziawg-tools` — форк `wireguard-tools`,
  вся специфика в параметрах конфига. Управление клиентами — это генерация
  конфига по шаблону, `awg syncconf` и учёт в json, и этого достаточно.

## Что делает установщик

1. Ставит базовое: `curl`, `gnupg`, `iproute2`, `iptables`, `qrencode`, `python3`.
2. Подключает **официальный PPA Amnezia** — ключ тянется с keyserver и сверяется
   по полному отпечатку `75C9DD72C799870E310542E24166F2C257290828`, а не
   принимается на веру.
3. Ставит `amneziawg` (метапакет → `amneziawg-tools` + `amneziawg-dkms`), докидывая
   `linux-headers-$(uname -r)` — модуль собирается dkms'ом под твоё ядро.
4. **Проверяет поколение**: `awg --version` и `modinfo -F version amneziawg` должны
   дать `3.x`. Не дали — собирает tools и модуль из исходников; и после этого не
   дали — падает, а не делает вид, что всё хорошо.
5. Фиксирует версии пакетов (`apt-mark hold`), чтобы `apt upgrade` не увёз сервер
   на поколение 4, пока клиенты сидят на третьем.
6. sysctl: `ip_forward`, форвардинг v6, `bbr` + `fq`, udp-буферы.
7. Генерирует конфиг интерфейса со **случайными** параметрами обфускации, ключом
   сервера и правилами NAT в `PostUp`/`PostDown`.
8. Кладёт `amwg`, раскладывает `state.json`, включает `awg-quick@awg0` и таймер
   учёта трафика, заводит первого клиента.

Что он **не** делает: не сносит `unattended-upgrades` и `cloud-init`, не требует
перезагрузок, не лезет в ssh и не настраивает fail2ban. Если `ufw` включён —
только открывает udp-порт.

### Флаги

| Флаг | По умолчанию | Что делает |
|---|---|---|
| `--endpoint HOST` | внешний ip (спрашивается у ifconfig-сервисов) | адрес, который попадёт в клиентские конфиги |
| `--port N` | `443` | udp-порт; 443 и 53 выглядят естественнее прочих |
| `--iface NAME` | `awg0` | имя интерфейса и имя конфига |
| `--subnet CIDR` | `10.9.9.0/24` | подсеть туннеля; в /24 влезает 253 клиента |
| `--dns A,B` | `1.1.1.1,1.0.0.1` | DNS для клиентов |
| `--wan IFACE` | из default route | внешний интерфейс для MASQUERADE |
| `--client-mtu N` | `1280` | MTU клиента; ограничения на S1/S2 в AWG считаются от него |
| `--keepalive N` | `25` | `PersistentKeepalive` |
| `--allowed-ips STR` | `0.0.0.0/0, ::/0` | что клиент заворачивает в туннель |
| `--client NAME` | `client1` | первый клиент; `--client ""` — не заводить |
| `--from-source` | нет | собрать tools и модуль из git, минуя PPA |
| `--single-headers` | нет | `H1-H4` одиночными числами вместо диапазонов |
| `--no-timings` | нет | не писать тайминги 3.0 |
| `--no-hold` | нет | не фиксировать версии пакетов |
| `--no-stats-timer` | нет | не ставить таймер накопления трафика |
| `--force-config` | нет | перегенерить конфиг интерфейса |
| `--amwg PATH\|URL` | рядом со скриптом или из `AWG_REPO_RAW` | откуда взять `amwg.py` |
| `--uninstall --yes` | — | снести всё, сложив ключи в `/root/awg-backup-*.tar.gz` |

Любой флаг можно задать переменной окружения: `AWG_PORT`, `AWG_SUBNET`,
`AWG_ENDPOINT`, `AWG_DNS`, `AWG_IFACE`, `AWG_WAN`, `AWG_CLIENT_MTU`,
`AWG_KEEPALIVE`, `AWG_ALLOWED_IPS`, `AWG_FIRST_CLIENT`, `AWG_REPO_RAW`.

> `--force-config` перевыпускает ключ сервера и всю обфускацию: **всем клиентам
> понадобятся новые конфиги**. Старый файл сохраняется рядом как `.bak-<дата>`.

## Куда что ложится

| Путь | Что |
|---|---|
| `/etc/amnezia/amneziawg/awg0.conf` | конфиг интерфейса: `[Interface]` от установщика, `[Peer]` от `amwg` |
| `/etc/amnezia/amneziawg/amwg/state.json` | клиенты: ключи, ip, вкл/выкл, заметки (0600) |
| `/etc/amnezia/amneziawg/amwg/traffic.json` | накопленный трафик и последний хендшейк |
| `/usr/local/bin/amwg` | утилита управления |
| `/etc/systemd/system/amwg-poll.{service,timer}` | учёт трафика раз в 5 минут |
| `/etc/sysctl.d/99-amneziawg.conf` | форвардинг, bbr, буферы |
| `/etc/apt/sources.list.d/amnezia-ppa.list` | репозиторий Amnezia |

## Утилита управления

Без аргументов — меню: стрелки, **цифры** (набирается и многозначный номер),
пробел — отметить несколько, Enter — подтвердить, `q`/Esc — назад. Нет живой
консоли (пайп, `ssh host amwg …`) — тот же выбор спрашивается номерами.

Всё то же самое доступно флагами:

| Команда | Что делает |
|---|---|
| `amwg list [-v] [--json]` | клиенты: ip, статус, последний хендшейк, трафик |
| `amwg add <имя> [--qr] [--note …] [--ip …]` | новый клиент + печать конфига |
| `amwg show <имя> [--qr] [--png ф] [--out ф]` | отдать конфиг: текстом, qr в терминал, картинкой, файлом |
| `amwg disable <имя>…` / `enable <имя>…` | снять пира с интерфейса, не теряя ключи |
| `amwg rm <имя>… [--yes]` | удалить насовсем |
| `amwg stats [<имя>] [--watch] [--json]` | трафик и последнее подключение; `--watch` — живая таблица со скоростью |
| `amwg server [--endpoint …] [--dns …] [--mtu N]` | параметры сервера и обфускации; с флагами — правка |
| `amwg apply` | перегенерить `[Peer]` и синкнуть на живой интерфейс |
| `amwg poll` | сложить счётчики в `traffic.json` (это делает таймер) |

Изменения применяются `awg syncconf` — **без рестарта интерфейса**: чужие сессии
не рвутся, добавление и удаление клиента незаметно для остальных.

### Что важно про эти фичи

- **Выключение** (`disable`) — это удаление пира с интерфейса при сохранении
  ключей и адреса в `state.json`. Для ядра «выключен» и «нет такого» неотличимы,
  так что клиент просто перестаёт подключаться; `enable` возвращает его как был.
- **Трафик.** Ядро считает байты от последнего подъёма интерфейса, а пир,
  которого сняли и вернули, начинает с нуля. «Всего за всё время» поэтому не
  существует само по себе — его складывает `amwg poll` из таймера (раз в 5
  минут). Отсюда две оговорки: между последним поллом и падением интерфейса
  теряется до 5 минут трафика, а `traffic.json` — единственное место, где эта
  история живёт. В колонке «принято/отдано» — текущая сессия, в `-v` — накопленное.
- **Последнее подключение** переживает рестарты: `poll` запоминает максимальный
  хендшейк и последний endpoint клиента, даже когда интерфейс потом лежал.
- **«Онлайн»** — хендшейк моложе трёх минут на поднятом интерфейсе. WireGuard
  переподписывается примерно раз в две минуты, так что для «сидит прямо сейчас»
  этого достаточно, а для «не отвалился ли» — смотри саму дату.
- **qr** делается `qrencode` из готового конфига. Конфиг с полным набором
  параметров 3.1 — это ~800 байт, qr выходит примерно в 48 строк терминала:
  читается телефоном нормально, но если окно маленькое — `--png` и открыть
  картинкой.
- **Приватные ключи клиентов лежат на сервере** (`state.json`, 0600). Иначе
  «покажи конфиг ещё раз» невозможно: приватный ключ в конфиг нужно вписать, а
  восстановить его из публичного нельзя. Кому так не годится:
  `amwg add <имя> --pubkey <ключ>` — клиент генерит пару у себя, сервер знает
  только публичную часть, а параметры для ручной сборки конфига берутся из
  `amwg server`.

## Про конфиг: что и почему

Все параметры обфускации, кроме `Jc/Jmin/Jmax`, **обязаны совпадать** у сервера и
клиента — это требование самой Amnezia, а не перестраховка. `amwg` копирует их
из серверного конфига в клиентский автоматически, сверять руками ничего не надо.

| Параметр | Значение по умолчанию | Зачем |
|---|---|---|
| `Jc`, `Jmin`, `Jmax` | случайные 4-12, 8-24, 64-320 | мусорные пакеты перед handshake; **у каждого клиента свои** |
| `S1`-`S4` | случайные 15-150 | мусор внутри служебных пакетов; при защите заголовков обязаны быть ≥ 12, и `S1 + 56 ≠ S2` |
| `H1`-`H4` | случайные непересекающиеся диапазоны | типы сообщений; в 3.0 это диапазоны, поэтому заголовок гуляет от пакета к пакету |
| `HeaderProtectionKey` | `awg genpsk` | ChaCha20 поверх заголовков WireGuard |
| `ContentPaddingAddition` | `8-32`–`48-96` | случайный паддинг полезной нагрузки |
| `RekeyAfterTime` и прочие тайминги | диапазоны вокруг дефолтов ядра (120/5/180/10/18) | чтобы тайминги соединения не были опознаваемой константой |
| `RandomTrailers` | `on` | случайные хвосты пакетов (3.1) |
| `DisableCookies` | `on` | отключение Cookie Reply (3.1) |
| `I1`-`I5` | выключены | сигнатурные пакеты пишутся руками под конкретную маскировку |

Две поправки к тому, что пишут в интернете и что было в исходном разборе темы:

- **`HeaderProtectionKey` — не hex.** В `amneziawg-tools` он разбирается тем же
  `parse_key`, что и обычные ключи: 32 байта в base64, то есть ровно то, что
  выдаёт `awg genpsk`. Hex не примут.
- **Пакет модуля называется `amneziawg-dkms`**, а `amneziawg-linux-kmod` — это имя
  исходного пакета на Launchpad. Ставится метапакет `amneziawg`, он тянет
  `amneziawg-tools` (бинари `awg`, `awg-quick`) и `amneziawg-dkms` (модуль).

`DisableCookies = on` — сознательный размен: cookie reply в WireGuard это защита
от DoS с подделкой адреса. Персональному серверу на пару человек она нужна меньше,
чем невидимость, но если сервер начнут долбить — параметр убирается из конфига
(и из конфигов клиентов) первым.

IPv6 внутрь туннеля не заворачивается: у интерфейса нет v6-адреса, а `::/0` в
`AllowedIPs` уводит v6-трафик клиента в туннель, где он гасится. Это не дыра, а
ровно то, что нужно — реальный v6-адрес наружу не течёт.

## Клиенты

Поколение 3.1 понимают только официальные приложения Amnezia:

| Платформа | Что ставить |
|---|---|
| Windows | `amnezia-vpn/amneziawg-windows-client`, релиз 3.1.0+ (есть standalone MSI) |
| Android | `amnezia-vpn/amneziawg-android` |
| iOS/macOS | `amnezia-vpn/amneziawg-apple` |
| Linux | `awg-quick` из тех же `amneziawg-tools` |

Сторонний WG Tunnel и прочие «поддерживаем AmneziaWG» — это поколение 1.5, с
конфигом отсюда они не заведутся. Если очень надо старого клиента — придётся
выкидывать из конфига всё, кроме `Jc/Jmin/Jmax`, `S1-S4`, `H1-H4`, и это уже
другой сервер, не этот.

## Если что-то пошло не так

**Модуль не грузится.** `dkms status`, `journalctl -k | tail`. Два частых случая:
нет `linux-headers-$(uname -r)` (поставить и `dkms autoinstall`) и включённый
Secure Boot — dkms-модуль тогда надо подписать (`mokutil --import`) или выключить
SB. Установщик про Secure Boot скажет отдельно, если увидит.

**В PPA нет сборки под мою серию.** Свежие сборки 3.1 лежат для `focal`, `jammy`,
`noble`. На более новых убунтах установщик берёт `noble` (бинарь tools совместим,
а модуль всё равно собирается dkms'ом под твоё ядро), на debian — `focal`, как
советует сама Amnezia. Не сложилось — `--from-source`.

**`--from-source` не собирает модуль.** Ядрам 5.6+ штатной сборке модуля может
понадобиться полное дерево исходников ядра, а не только заголовки: положить его
и слинковать в `/usr/src/amneziawg-1.0.0/kernel`. Это дорога для крайнего случая;
нормальный путь — PPA, где модуль собирается пакетом.

**Совсем не хочется ядерного модуля.** Тот же конфиг работает с userspace-
реализацией: поставить `amneziawg-go` и поднимать интерфейс как
`WG_QUICK_USERSPACE_IMPLEMENTATION=amneziawg-go awg-quick up awg0`. Ценой
процессорного времени — go-реализация заметно тяжелее.

**Клиент подключился, а сайтов нет.** Смотреть в таком порядке: `awg show awg0`
(хендшейк есть?), `sysctl net.ipv4.ip_forward` (=1?), `iptables -t nat -L
POSTROUTING -n` (MASQUERADE на месте? его ставит `PostUp`, значит интерфейс
поднимался через `awg-quick`, а не `ip link`). Если MTU где-то режет — уменьшить
`--client-mtu` до 1200 и перевыпустить конфиги.

**Порт занят.** Установщик проверяет и падает заранее: `ss -lunp | grep :443`.

**Обновиться на новое поколение.** Версии зафиксированы:
`apt-mark unhold amneziawg amneziawg-dkms amneziawg-tools && apt upgrade`, потом
`install.sh --force-config` и раздать всем новые конфиги. Пока клиенты не
обновились — не трогать: 3.0+ не обслуживает клиентов 2.0 на том же интерфейсе.

## Чего здесь нет

- Веб-панели и http-раздачи конфигов: конфиг с ключом — это секрет, его отдают
  qr-кодом с экрана или файлом по scp, а не ссылкой.
- Сроков жизни клиентов и квот по трафику: считать байты `amwg` умеет, резать
  по лимиту — нет.
- Настройки самого хоста (ssh, fail2ban, автообновления): не его дело.

## Мелочи эксплуатации

Файлы приезжают с винды по sftp без бита исполняемости, поэтому запускать
установщик надо через `bash install.sh`, а не `./install.sh`. Сам `amwg`
кладётся на сервер через `install -m 0755`, так что права у него правильные.

```sh
journalctl -u awg-quick@awg0 -n 50     # что было с интерфейсом
systemctl restart awg-quick@awg0       # перечитать конфиг целиком (рвёт сессии)
amwg apply                           # то же самое без разрыва сессий
systemctl list-timers amwg-poll.timer
```
